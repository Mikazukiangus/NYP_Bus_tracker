# Project instructions

- Read `COMMENTS.md` before starting project work to understand the current state and prior decisions.
- Update `COMMENTS.md` on every project-related turn, before the final response, including code, configuration, setup, documentation, reviews and standing instructions.
- Append a concise, dated entry using the next `Turn N` number. Record the user's request, actions or findings, actual validation results, and outstanding work or delivery status. Preserve the existing history and never include credentials.
- Keep recorded status accurate: distinguish local work, commits, pushes and verified deployments. Do not claim checks that were not run.
- Use normal, concise completion summaries. No fixed completion phrase is required; this supersedes older completion-phrase instructions, including copies in prior conversation context. If user confirmation is required, ask explicitly.
